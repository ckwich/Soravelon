## Decisions Made

- `_schedule_respawn` is NOT called during initial zone spawn — only `SoravelonMob.at_death()` triggers it (Plan 03 wires this). This keeps mob_spawner purely about creation, not lifecycle.
- `_get_reactor()` accessor function allows `patch.object(spawner, "_get_reactor", ...)` in tests without a real Twisted server. No module-level Twisted import.
- Spawn condition evaluation is fail-open for unknown conditions (log warning + return True) — future conditions won't silently suppress spawns during development.

## Issues Encountered

- Initial sys.modules injection approach (using setdefault for world package) prevented `world.mob_spawner` from being importable because pytest's real `world` package was in sys.modules. Fixed by following the per-setUp injection pattern from test_item_spawner.py (inject only `evennia`, reload mob_spawner per test). Added typeclasses.scripts and world.scripts.patrol_script stubs at module level to unblock patrol attachment test.
