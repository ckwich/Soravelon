# Phase 3.1: Mob & Item Spawn Runtime - Context

**Gathered:** 2026-03-25
**Status:** Ready for planning (REVISED — major scope corrections applied)

<domain>
## Phase Boundary

Create the mob, item, and loot runtime systems. Mob spawner reads spawn_definitions from rooms and creates SoravelonMob instances with affixes, combat stats, patrol scripts, and respawn timers. Item spawner creates items from zone-scoped template definitions. Loot tables resolve skill-based drops on mob death. Named mobs are MERGED into the standard spawn definition schema (no separate registry).

**Key architectural change:** Named mobs are NOT a separate system. They are spawn definitions with extra fields (prestige_modifier, tome_drop, spawn_condition, sequence). `named_mob_registry.py` is DELETED. `area.named_mob()` becomes a thin wrapper around `area.spawn()`.

</domain>

<decisions>
## Implementation Decisions

### Spawn Timing
- **D-01:** Mobs spawn at zone load time (during `_load_all_zones()`).
- **D-02:** Spawning approach is Claude's discretion (stagger or synchronous).
- **D-03:** On server reload, PRESERVE existing mobs. Only spawn for rooms under count_min.
- **D-04:** `no_mobs` room tag (category="room_flag") prevents mob entry, spawning, AND patrol routing.

### Respawn Mechanics
- **D-05:** Per-room respawn timer from spawn definition's `respawn_minutes ± respawn_variance`.
- **D-06:** Respawn timers NEVER hardcoded — always from the spawn definition.
- **D-07:** On server restart, all dead mobs respawn immediately.

### Spawn System Architecture
- **D-08:** New module: `world/mob_spawner.py`. Stateless functions.
- **D-09:** Call chain: mob_spawner → apply_affixes_to_mob() → initialize_mob_combat_stats().
- **D-10:** `spawn_zone(zone_obj)` iterates rooms by zone_id tag, calls `spawn_room_mobs(room)`.
- **D-11:** `spawn_room_mobs(room)` reads `room.db.spawn_definitions`, rolls count, creates mobs.

### Named Mobs MERGED Into Spawn Definitions
- **D-12:** DELETE `world/named_mob_registry.py`. Named mobs are NOT a separate system.
- **D-13:** Named mob fields folded into spawn_definitions: `is_named` (bool), `prestige_modifier` (float), `tome_drop` (str or None), `spawn_condition` (str or None), `sequence` (list or None).
- **D-14:** `area.named_mob()` in AreaBuilder becomes a thin wrapper around `area.spawn()` with the extra named fields. Deprecate the separate `named_mob_definitions` room attribute.
- **D-15:** Named mobs tracked by tag (`mob_type` in category `mob_id`) for idempotent reload detection. No separate registry — search_tag is sufficient.
- **D-16:** Named mob respawn uses the same `respawn_minutes` field as any other spawn definition. Custom respawn timer = just a longer respawn_minutes value.
- **D-17:** Named mob dies → zone announcement via direct room broadcast (NOT action_vocabulary) → respawn timer → new instance.
- **D-18:** Tome drops PRE-ASSIGNED at spawn (`mob.db.tome_drop`). On death, item created via item_spawner.

### Item Spawn System
- **D-19:** New module: `world/item_spawner.py`. Creates item instances from template definitions.
- **D-20:** Item templates are DATA-DRIVEN DICTS stored in AREA FILES via `area.item()` method. Stored on `zone_obj.db.item_definitions`. NOT a hardcoded Python registry.
- **D-21:** `area.item(item_id, **kwargs)` new AreaBuilder method. Stores on zone_obj.db.item_definitions list. Same pattern as area.spawn().
- **D-22:** `create_item_from_template(item_def, location=None)` creates SoravelonItem/Equipment/Container from a definition dict.
- **D-23:** Item definitions define: key, item_type, weight, rarity, equip_slot (if equipment), desc, and any special properties.

### Action Vocabulary — Wire Stubs
- **D-24:** Wire `_action_give_item` to accept `template_id` → calls item_spawner to create, then pick_up().
- **D-25:** Wire `_action_take_item` to use inventory_engine.drop_item() for real removal.
- **D-26:** Wire `_action_spawn_mob` to use mob_spawner.spawn_single_mob() for real mob creation.

### Patrol Integration
- **D-27:** `_maybe_attach_patrol()` in mob_spawner. After creating mob, checks zone_obj.db.patrol_definitions for matching mob_template. Attaches PatrolScript.
- **D-28:** `find_path()` in patrol_engine.py respects `no_mobs` room tag during BFS.

### Count Management
- **D-29:** count_min/count_max per spawn definition. Roll target on initial spawn.
- **D-30:** On reload, count existing mobs in room. Only spawn up to count_min if under.
- **D-31:** Respawn timer only fires if current count below count_max.

### Loot Table System
- **D-32:** Extend `world/loot_tables.py` to functional loot resolution. `roll_loot(mob, killer)` returns list of item definition dicts to drop.
- **D-33:** Loot tables are data-driven dicts. Each zone can define loot overrides via `zone_obj.db.loot_table_overrides`.
- **D-34:** Drop quality determined by KILLER'S RELEVANT SKILL SCORE (0-25 tier 1 through 91-100 tier 5). NOT level-based. Uses existing `get_material_tier()` from zone_scaling.py.
- **D-35:** `roll_loot()` called from `at_death()`. Items created via item_spawner and placed in room. Group loot enforcement deferred to Phase 6.
- **D-36:** Read `C:\Obsidian\brain\Soravelon\soravelon-crafting.md` for the skill-based material tier design. Do NOT implement level-based loot.

### Claude's Discretion
- Stagger approach for zone spawn
- Respawn timer implementation (Twisted callLater recommended)
- Loot table dict format details
- Named mob zone announcement text format
- How area.named_mob() wraps area.spawn() internally

</decisions>
