# Phase 03.1 Plan 04: Skill-Based Loot Resolution Summary

**One-liner:** Functional loot engine using killer skill score (0-100) → material tier (1-5) via `get_material_tier()`; mob rarity adds extra rolls; zones override per mob_type via `loot_table_overrides`.

## What Was Built

Extended `world/loot_tables.py` from a 19-line stub to a full loot resolution engine. `roll_loot(mob, killer)` returns a list of `item_def` dicts that `item_spawner` will create and place in the room on mob death (wired in plan 03.1-05).

### Core Design (D-34 compliance)

Drop quality is determined **exclusively** by the killer's relevant domain skill score. The same wolf in the same zone drops different quality pelt depending on the character's `combat` score — not their backend level, not the zone's difficulty:

```
Skill  0-25  → Tier 1 (rough)      → rough, matted wolf pelt         / value 2
Skill 26-50  → Tier 2 (standard)   → standard wolf pelt              / value 5
Skill 51-75  → Tier 3 (quality)    → quality wolf pelt               / value 10
Skill 76-90  → Tier 4 (refined)    → refined wolf pelt               / value 20 / rarity magic
Skill 91-100 → Tier 5 (exceptional)→ exceptional wolf pelt           / value 40 / rarity rare
```

### Module Structure

- `get_zone_obj_for_room(room)` — module-level wrapper, patchable in tests
- `get_material_tier(skill_score)` — module-level wrapper, patchable in tests
- `LOOT_TIER_MODIFIERS` — preserved from stub (extra_rolls, tome_chance, ancient_chance per rarity)
- `get_loot_modifiers(mob)` — preserved from stub
- `LOOT_TABLES` — data-driven dict keyed by mob_type; wolf entry as Phase 7 template
- `_resolve_loot_table(mob)` — checks zone overrides first, falls back to LOOT_TABLES
- `_pick_drop(drops, count)` — weighted random selection from drops pool
- `_build_item_def(drop, tier)` — assembles item_def dict at tier index
- `roll_loot(mob, killer)` — public API; returns list[dict] (may be empty)

### Zone Overrides

Zones can replace any LOOT_TABLES entry for a mob_type by setting `zone_obj.db.loot_table_overrides = {"wolf": {...}}`. This allows zone-specific drops (e.g., wolf fangs in a volcanic zone) without modifying the global table.

## Tests

25 tests in `tests/test_loot_tables.py` using `unittest.TestCase` + `MagicMock`. No Evennia DB required.

**Coverage:**
- Tier boundary tests: skill 0, 25, 60, 76, 100 → correct tier values/rarities/descs
- Drop chance gate: `base_drop_chance=0.0` always empty, `1.0` always drops
- Extra rolls: normal(0), magic(1), legendary(2) extra rolls → 1/2/3 total item_defs
- Zone override: mock zone_obj with `loot_table_overrides` returns override items
- Fallback: no zone_obj → LOOT_TABLES used; no location → LOOT_TABLES used
- Null safety: `domain_scores=None` defaults to skill 0 → tier 1
- Missing skill key: combat missing from domain_scores → 0 → tier 1
- Relevant skill: `relevant_skill="naturalism"` uses naturalism score not combat
- Item def shape: all 7 keys present (item_id, key, item_type, weight, rarity, value, desc)
